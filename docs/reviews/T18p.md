## Review

1. `functions/api/extract.ts:139`, should-fix: the 429 message always says "Wait a minute", but once the hourly window is full `Retry-After` can be up to 3000 seconds (the test uses exactly 3000), so the message does not match the real wait. Choose the wording by `retryAfterSec` (try again in a few minutes / in about an hour), and add "Your notes are kept", as the other errors do (R11.3; contract §4 requires the message to say what the user can do).
2. `functions/_lib/rateLimit.ts:77`, nit: the IP is hashed with unsalted SHA-256. The IPv4 space is small enough to brute-force, so "no plaintext stored" is only a weak guarantee. Add a salt from an env secret (HMAC), or state this in the contract. The code logs neither the IP nor note text, so this part of the privacy requirement R1.5 holds.
3. `functions/_lib/rateLimit.ts:116`, nit: every live request adds 4 Cache API subrequests (2 match, 2 put), and the put is awaited, which adds latency. Handing the put to `waitUntil` removes that latency, but the subrequest count stays the same. Whether the live path's total subrequests, including the LLM and grounding, come close to 50 was not counted in this review.
4. `functions/api/extract.ts:122-134`, confirmed fine: the demo path (caseId plus the exact narrative), the fallback when the AI binding is missing, and manual add through `/api/terms` are not rate-limited (R10.3, R10.4, R2.7). The 429 is built by `apiError`; its shape and `retryable: true` follow contract §4 and R11.6; the app already has RATE_LIMITED copy in `states.tsx:35` and shows retry based on `retryable`. The §7 safety framing and the scope are unaffected; only the 4 declared files changed.
5. `docs/CONTRACT.md:408`, nit: the contract says only that the "demo extraction (step 2)" is not limited. In fact, when a user pastes a demo narrative without the caseId and the AI binding is present, the request goes through the live path and is counted. Add a sentence next to it.

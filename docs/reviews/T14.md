## Findings

1. **`app/src/features/review/ReviewStep.tsx:46, 87`, should-fix**
   - **Problem:** the status before removal lives only in the component's `previousStatus` ref. If the user removes Seizure (originally not present), goes to the matches page and comes back, the ref is cleared. Clicking Restore in "Removed" then restores it to `observed` by default. As a result, "never had a seizure" is sent to ranking as "has seizures". This breaks R2.6 (undo should return to the original state), R4.4, and the data faithfulness that design §7 "Show the reasoning" requires.
   - **Fix:** persist the pre-removal status with the case, for example in the store's meta (a shared file, which needs its own claim). Or, inside review, derive the original status from the `quote` and the extraction result. When the original status cannot be found, do not default to observed; let the user choose.

2. **`app/src/features/intake/IntakeStep.tsx:39, 43`, should-fix**
   - **Problem:** text over 8,000 characters lives only in component state (`overflow`); the store holds the last valid value before truncation. When the user leaves the Notes step or reloads, the overflow is lost. R1.2 requires "keep the text", and contract §4 requires "The client keeps all user input".
   - **Fix:** persist the over-long draft too (for example in meta or sessionStorage), or block leaving the current step while it is over the limit and say why.

3. **`app/src/features/intake/IntakeStep.tsx:197`, `DemoPicker.tsx:59`, should-fix**
   - **Problem:** when offline, "Find the features" and manual search are disabled, but the demo picker is not. Clicking a demo offline jumps to the features page and then reports an OFFLINE error (`api.ts:261` throws straight away when offline and does not use mocks). This breaks R11.5.
   - **Fix:** disable the demo options when offline and say why. Or, when offline, use the bundled demo extraction directly and label it as demo data.

4. **`app/src/features/review/ReviewStep.tsx:73, 83, 104` and `:339`; `ManualAdd.tsx:243-255`; `IntakeStep.tsx:56, 165`, nit**
   - **Problem:** the same event is announced twice by screen readers: once by `announce()`, and again by the surrounding `aria-live` or `role="status"` region. For example, the actionBar text changes when a status changes, and `lastAdded` appears when a term is added. R12.3 asks for a single polite announcement.
   - **Fix:** keep only one announcement channel per kind of event.

5. **`app/src/features/review/TermRow.tsx` and `ReviewStep.tsx`, nit**
   - **Problem:** R2.6 says "confirm", but there is no explicit confirm action; terms count as confirmed by default. Contract §5's `TermStatus` has no confirmed state either, so this is consistent with the contract.
   - **Fix:** add one line to the hint, "kept as present means confirmed", or propose to Ian that the requirement wording change.

6. **`app/src/features/review/model.ts:84`, nit**
   - **Problem:** a quote that overlaps an earlier quote is silently skipped and not highlighted. But the row's `range` is not null, so "Not found in the current notes" is not shown either. The R2.5 hover highlight fails for such terms, with no notice at all.
   - **Fix:** give the row of a skipped quote a visible mark, or merge the overlapping spans into one highlight.

7. **`app/src/features/review/NotesPanel.module.css:155-163` (collapse on narrow screens), nit**
   - **Problem:** on phones the notes are collapsed by default. When a term in the list is hovered or focused, its quote may be hidden in the collapsed area. R2.5 is only partly met on phones.
   - **Fix:** when activated and the quote is in the collapsed area, expand it or scroll to it.

8. **`app/src/features/intake/IntakeStep.tsx:105`, `ReviewStep.tsx:99`, nit**
   - **Problem:** `behavior: 'smooth'` is hard-coded in JS. The CSS reduced-motion rule cannot suppress smooth scrolling started from JS, which breaks R12.6.
   - **Fix:** use `'auto'` under `prefers-reduced-motion: reduce`.

9. **`app/src/features/intake/errorCopy.ts:23`, nit**
   - **Problem:** "8,000" is hard-coded instead of using `LIMITS.notesMaxChars`.
   - **Fix:** build the number from the constant so the two places cannot drift apart.

10. **`app/src/features/review/LocalIcon.tsx`, nit**
    - **Problem:** a separate icon set is started inside the feature directory. The comment already says it should later move to the shared `components/ui/Icon.tsx`.
    - **Fix:** record a follow-up shared-file task on the board, so other features do not each copy their own.

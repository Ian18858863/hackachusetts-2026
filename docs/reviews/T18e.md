2. **`functions/_lib/fallback/rank.ts:323-349`, nit:** the 12 s budget is timed from inside `fallbackRank`, not from the start of the request, so request parsing and the cache read are not counted. The real gap is only a few milliseconds, which is acceptable. To be strict, the handler could pass in the request start time. The worst case is Monarch 10 s plus annotation/Orphadata capped at the remaining time, ≤12 s in total, which meets §7.4 and R11.4 (on failure only that source's data is dropped).
3. **`functions/_lib/fallback/rank.ts:365-369`, should-fix (present before this change; not introduced by this diff):** counting subrequests at the maximum `limit` of 10: Monarch 1 + 1 retry, plus 10 × 2 annotations × 2, plus 10 Orphadata × 2, about 62 in total, over the free plan's 50. The default `limit=5` is about 32, which is fine. Fix: when `limit>5`, fetch only one of the ORPHA or OMIM annotations, or turn off the retry. I did not verify whether Cache API calls count toward the limit of 50.

### Findings

1. **`app/src/styles/tokens.css:99,101,103,105` (should-fix)**
   - Problem: the compatibility block's comment says "do not add raw values", but it still holds 4 raw colour values (`#2447a3`, `#c9d4f0`, `#8f3a2e`, `#6b4a00`). They are not in the token sheet, and the contrast table in the file header has no figures for them. design.md §5 requires contrast to be measured with a tool.
   - Fix: add the measured contrast of these 4 values to the file header comment. If a value does not need to exist on its own, map it to a token in the sheet.

2. **`app/src/styles/tokens.css:179` (nit)**
   - Problem: `--weight-medium: 500` falls back to 400 on Source Sans 3, because only 400 and 600 are loaded. No code uses it now, but if T14–T16 feature code uses the old name for emphasis, the bold will not show.
   - Fix: remind T14–T16 in their task notes to use 600, or map this compatibility name straight to 600.

3. **`app/src/styles/tokens.css:104,137` (nit)**
   - Problem: `--color-danger-tint` now equals `--surface`, so error states no longer have a tinted background. This follows "No red", but if feature code uses it to mark the contradicted state, there will be no visible colour difference.
   - Fix: state in the feature tasks that the contradicted state must carry a text label or icon (R12.4).

4. **`app/src/shared/ui/Disclaimer.tsx:6` (nit)**
   - Problem: if `'. '` is not found in `DISCLAIMER`, `SPLIT` becomes 0 and the bold part is empty. This is fragile.
   - Fix: when the separator is missing, output the whole sentence, or add a unit test that locks the string's format.

5. **`app/src/shared/ui/AppFooter.module.css:14` (nit)**
   - Problem: the safety sentence in the footer is now 14px. The results page header has another copy at 19px, so R9.1 and §7 "body size" are still met. But the notes and features steps show this sentence only in the footer.
   - Fix: acceptable. To be safer, raise the footer `.safety` to `--t-sm` or `--t-base`.

6. **`app/src/components/shell/TopBar.tsx:16` (nit)**
   - Problem: "Prepare brief" shows as soon as there is one observed term. But `/api/brief` also requires `lastRanking`, otherwise it returns 400 (contract §7.7).
   - Fix: also require `lastRanking` to show it, or confirm that the brief step (T16) handles the "not ranked yet" empty state (§8 designed states).

7. **`app/src/components/shell/TopBar.module.css:85` (should-fix, needs measurement)**
   - Problem: below 1120px wide, the step navigation wraps to a second line. At 1000×600 the header is about 130px; adding the kicker, the 44px title, the lede with the safety sentence and the label row may push the rank-1 name and the first piece of evidence below the fold. This breaks design.md §4 and the ART_DIRECTION requirement "above the fold at 1000×600".
   - Fix: confirm with a screenshot at 1000×600. If it overflows, compress the header or title sizes at the `max-height: 700px` breakpoint.

8. **`app/src/styles/base.css:138` (nit)**
   - Problem: in reduced-motion mode, the global `animation: none !important` stops both the spinner and the skeleton shimmer. This follows R12.6 and ART_DIRECTION.
   - Fix: confirm that `LoadingPanel` still shows the real step text when static (R11.1).

**Verdict: REVIEWED** (no blocker; handling 1 and 7 before merging is recommended).

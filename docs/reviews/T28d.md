## Review

1. `app/src/shared/i18n/messages/brief.ts`, es `overlapStrong` / `overlapWeak` (should-fix): "Coincidencia alta / baja" reads like "high match". Coincidencia here is the same word as in "posible coincidencia" (possible match), so it sounds closer to a conclusion than the English "Strong overlap" (feature overlap), which goes against design.md §7 (never look like a verdict). Change to "Solapamiento fuerte / parcial / débil".
2. `brief.ts`, es and fr `featureCounts` (nit): "{present} presentes" / "{present} présentes" is the wrong plural when the count is 1; the English has no such problem. Split into singular and plural keys as `matchesOne` / `matchesMany` do, or rephrase to a count-independent format such as "Presentes: {present}".
3. `brief.ts`, ja `testsHeading` 「尋ねる検査」 and `questionsHeading` 「尋ねる質問」 (nit): the meaning is right but they read stiffly. Could be 「医師に相談したい検査」 and 「医師に尋ねたい質問」.
4. The status value "Recruiting" in `app/src/features/trials/TrialsPanel.tsx` and `Phase ${…join(' and ')}` in `app/src/features/trials/format.ts` (nit): "and" is the app's own word, left in English under the "phase names stay English" convention. If that is intended, fine; otherwise move the joining word into the dictionary.
5. `apiText` in `app/src/shared/api.ts` (nit): the app's own error text is fixed in the language active when the error happened; if the user switches language afterwards, an error already on screen does not change. No behaviour impact; note it only.
6. Passing: every deleted English literal compared with the en dictionary, all byte-identical (including `fileRef`, `noneSearch`, `seeAll` and `OFFLINE_MOCK_LABEL` after JSX line joins). Placeholders are consistent across languages; `format` replaces once and leaves unknown placeholders for `fillTemplate`; no sentence concatenation. HPO labels, disease names, trial data, ids, the server's §13 text and demoLabel are not translated. In non-English locales the translation is shown first and then the server's English original, with `lang="en"`. The changes only affect how copy is read; all changed files are inside the claimed scope. The zh, ko and fr safety copy is faithful, neither stronger nor weaker than the original.

**Verdict: CHANGES_REQUESTED** (only because of item 1).
**NOT RUN:** the worktree has no `app/node_modules`, so `tsc`, `messages.test.ts` and vitest were not run; nothing was rendered in a browser or print preview (including the layout of the bilingual disclaimer with long text).

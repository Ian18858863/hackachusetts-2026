## Review

**T18b review result** (worktree uncommitted, `cf82644..HEAD` is empty; reviewed `respond.ts` and all untracked files in `git diff cf82644`)

1. **`functions/api/rank.ts:100`, should-fix.** Whenever `source === "live"`, the response is cached for 24 h, so degraded results are cached too. For example, if a candidate has an ORPHA/OMIM id but the annotation call fails temporarily (`sources` lacks `"hpo-annotations"`, `frequency: null`), this incomplete evidence is kept for a whole day. R11.4 allows degrading only the current request, not fixing the degradation in place. Fix: when any candidate lacks annotations because of an upstream failure, do not write the cache, or use a very short TTL.

2. **`functions/_lib/fallback/questions.ts:71,75,85`, should-fix, involves safety wording.** When a candidate has no annotation set (404 → `null`), all its features are written as "not listed for <id>", so every feature of the other candidates looks discriminating. MONDO-only candidate ids are also sent to the JAX annotation API. If JAX answers 400, `getJson` throws `UpstreamError` and the whole request becomes a retryable 502, but retrying will never succeed. This breaks the spirit of §7.5 step 6 ("not listed" may only mean it was really looked up and is really not listed) and R5.4 and R9.3. Fix: do not send MONDO ids to JAX; mark candidates with no annotation set as "no annotation data", leave them out of the max−min calculation and out of `why`.

3. **`functions/_lib/fallback/questions.ts:71` (compare `rank.ts:275`), should-fix.** rank merges the ORPHA and OMIM annotation sets; questions looks up only the `diseaseId` in the request (usually ORPHA). As a result, a feature that appears only in OMIM is listed as common in rank's `notReported`, but questions says "not listed for <the same disease>". The two screens contradict each other. Two fixes: give questions the same OMIM xref as rank (passing the xref needs a `[CONTRACT CHANGE]`), or state in `why` which annotation set it refers to.

4. **`functions/api/brief.ts:102-117`, should-fix.** Only the presence of the candidates array is checked, not its elements. `fallback/brief.ts:72-74` accesses `e.frequency?.source.startsWith`, and `:53-58` accesses `gene.symbol`. If the client sends a malformed case, one of two things happens: a TypeError becomes a 500 `INTERNAL` (§4 says malformed input should return 400), or a test suggestion like "includes undefined" is generated, which breaks R6.3 and P13. Fix: check that `genes[].id/symbol` and `frequency.source` are strings, and return 400 `INVALID_REQUEST` when they are not.

5. **`functions/api/rank.ts:92`, `next-questions.ts:90`, `trials.ts:87`, should-fix.** The demo fallback only forces `source: "demo"` and does not guarantee that `dataVersions.demoCache` is present (the §7.4 failure-handling table requires it to be set). Fix: fill it in when missing, or assert that the recordings always have it. Also, `ENGINE_STATUS` shows the recordings are empty at the moment, so these three fallback paths can never be hit now; R11.2 is not actually met yet, and recording the demo video depends entirely on live Monarch. This is in the scope of Jerry's 1.9; noted here only as a risk.

6. **`functions/_lib/fallback/**` (the whole directory), should-fix, process issue.** This layer re-implements the domain logic of §7.4 and §7.5 under Ian's paths: the organ-system-level subsumer list, frequency midpoints, the notReported/contradicted rules. §2 and §3 assign these to `engine/**` (Jerry's T07). The code comments make clear this is temporary, and `engineFirst` switches only on `NotImplementedError`, so the design is sound. But it overlaps the T07 scope, and needs Jerry's explicit approval in the group chat, with an agreement to delete it once the engine is live.

7. **`functions/api/rank.ts:58`, `next-questions.ts:51`, nit.** An over-large request body returns 413 `TEXT_TOO_LONG`, but §4 defines that code as "`text` over 8,000 characters". By §4, an id list over the limit should be 400 `INVALID_REQUEST`.

8. **`functions/_lib/fallback/http.ts:67` together with `rank.ts:291`, `trials.ts:62`, nit.** When Monarch or ClinicalTrials.gov returns 404, it becomes 200 with an empty list. For trials, the user sees "no recruiting studies" (R7.2), while the real cause is an upstream error. Fix: for these two upstreams, treat 404 as `UpstreamError` too.

9. **`functions/_lib/fallback/trials.ts:43`, nit.** ClinicalTrials.gov returns phase `"NA"` for some studies, and it is passed through as is. §5 says "[] when there is no phase". Fix: filter out `"NA"`.

10. **`functions/api/rank.ts:73,80`, nit.** The cache key does not distinguish the engine path from the fallback path. After Jerry's engine goes live, fallback-computed results may still be returned for up to 24 h. Fix: add the path or the engine version to the key.

11. **`functions/_lib/fallback/questions.ts:25`, nit.** `HPO_VERSION_UNKNOWN` is imported from the fallback `rank.ts`, while the engine already has `HPO_VERSION` with the same value (`engine/hpo.ts:16`). Fix: use the engine's constant, so only one place changes once open question 6 is settled.

## Review

**CHANGES_REQUESTED.** Family mode leaks disease names through the demo case id, and one deviation from the §13 safety text needs a decision.

1. **blocker**, `features/brief/FamilyBrief.tsx:140-141`: the print `document.title` (which is also the browser's default PDF file name) uses `caseObject.demo.caseId`, so it shows `demo-marfan`, `demo-dmd`, `demo-cdls`, `demo-kabuki` or `demo-npc1`, all disease names or abbreviations. Fix: in family mode use `tb('printTitleCase')` or other neutral text.
2. **blocker**, `FamilyBrief.tsx:128,153,179`: `phenopacketFileName(data.phenopacket)` produces a file name like `phenopacket-rdd-demo-marfan-….json`, which appears in the save hint and is read out by the screen reader through `announceSaved`. Fix: in family mode use a neutral file name, and keep the id out of the hint and the announcement. The `id` and `subject.id` (`DEMO-synthetic-demo-marfan`) inside the phenopacket JSON also contain the disease name; those are generated by the server, so contract §7.7 needs a rule for family mode.
3. **should-fix**, `components/shell/StepHeader.tsx:73-79`, `FamilyBrief.tsx:264-271`: family mode keeps only the first sentence of the §13 disclaimer and replaces the second with `banner`. §13 and R9.1 require that sentence verbatim on the brief and every result screen. Dropping the second sentence when no candidates are shown makes sense, but first post a `[CONTRACT CHANGE] §13` and do it after approval.
4. **nit**, `shared/ui/AppFooter.tsx:26`: in family mode the Monarch line "Ranking by…" is still shown, although the page shows no ranking (§13 says "when Monarch results appear"). Suggest hiding it in family mode.
5. **nit**, `App.tsx` and `useDemoParam`: `?demo=demo-marfan` in the address bar also carries the disease name. Suggest documenting it as a known limit, or using a neutral parameter in family mode.
6. **Translations**: in all 6 languages, safety-related meanings such as `banner`, `reason` and `phenopacketNote` are faithful, neither stronger nor weaker than the English. Placeholders are consistent; no sentence concatenation. HPO labels, `q.question` and the §13 licence lines (with `lang="en"`) stay in the original. No English string was deleted or changed; only code such as `downloadJson` moved.
7. **Scope and logic**: apart from `features/brief/download.ts` and `TopBar.tsx`, `TopBar.module.css`, all files are inside the claim. Those three look like they belong to `components/shell/**` or the brief scope, which is acceptable, but best to note it on the board. Clinician mode has no logic change besides the switcher.

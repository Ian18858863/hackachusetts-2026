## Findings

1. **`.kiro/steering/medical-data.md:19`, should-fix**
   - Problem: this line forbids invented IDs anywhere, fixtures included. But the file covers `engine/**` through `fileMatch`, which includes `engine/test/**`. P1 needs "invented or unknown ids" in mocks precisely to verify that they are rejected (CONTRACT §11). The contract itself has the placeholder `ORPHA:99999`. Applied literally, Jerry's Kiro may refuse to write the P1 tests or weaken the rule.
   - Fix: state an exception. Test inputs may use IDs clearly marked as synthetic, but those IDs must never enter `engine/demo/**`, runtime data or responses.

2. **`.kiro/steering/medical-data.md:10–49`, should-fix**
   - Problem: several contract rules that directly govern `engine/` and `functions/` are missing:
     - Functions must not log note text; error messages contain no stack traces and no note text (CONTRACT §2, §4, R1.5).
     - The LLM prompt must say "copy phrases verbatim, do not diagnose, do not output diseases", and `label` is always the HPO primary name (CONTRACT §7.2 steps 4–5, R2.2).
     - An unannotated frequency must be written as "not listed for" or "frequency not listed", never as "absent in" (CONTRACT §7.5 step 6, R3.7).
     - The phenopacket contains no `diseases` and no `interpretations` (CONTRACT §7.7, R6.5).
     - Responses from the demo cache must carry `source: "demo"` and `dataVersions.demoCache` (CONTRACT §4, §9, R10.5). Line 36 only says "labelled as demo" and does not name these two fields.
   - Fix: add one line for each, citing the contract section.

3. **`.kiro/hooks/contract-drift-check.json:10`, should-fix**
   - Problem: the prompt compares the contract only with the spec and `app/src/shared/contract.ts`, and the latter does not exist yet. CONTRACT §5 and §6 say the source of truth for types and signatures is `engine/types.ts` and `engine/index.ts`, and the prompt does not include them. Once Jerry's engine lands, that is exactly where drift is most likely.
   - Fix: add `engine/types.ts` and `engine/index.ts`, handled "read only if present" like the app file.

4. **`.kiro/hooks/README.md:26`, should-fix**
   - Problem: "None … edits repo files" overstates it. The `agent` action of `contract-drift-check` starts a full agent loop with write tools. "Does not change files" is only a request in the prompt; nothing enforces it.
   - Fix: state plainly that this hook is read-only because of a prompt constraint, not because of permissions.

5. **`.kiro/steering/release-check.md:34–36`, should-fix**
   - Problem: the release check is not specific enough, in four places:
     - "the app opens with a demo example preloaded" does not check that the landing page CTA opens `/app/?demo=demo-dmd` (R10.6).
     - It does not check that the demo label `Demo case (synthetic narrative from phenopacket-store <id>)` appears on notes, results and exported files (R10.2, R6.6).
     - The safety line is only required on "results and brief". R9.1 and design.md §7 require it on every result page, including questions and trials.
     - It does not check the Monarch, Orphanet, ClinicalTrials.gov and phenopacket-store attributions (R8.2).
   - Fix: add a check item for each.

6. **`.kiro/steering/release-check.md:18–37`, should-fix**
   - Problem: it does not reference the definition of done in design.md §12: screenshots at three sizes, the happy path with keyboard only, reduced motion, contrast measured with a tool, loading/empty/error states triggered on purpose, every number with a source or demo label, and reporting what was not checked as NOT RUN. Ticking this checklist could report "ready to ship" without §12 being done.
   - Fix: add a section that requires PASS / FAIL / NOT RUN for each item of design.md §12.

7. **`.kiro/steering/release-check.md:24` and `:34`, nit**

   - Fix: check `version`, `source` and `llm.binding`, and run one `POST /api/extract` for `demo-dmd`. If the smoke script from tasks 5.1 already exists, point to that script instead.

8. **`.kiro/steering/medical-data.md:53`, nit**

   - Fix: keep the line and explain why, or point only to the specific sections.

9. **`.kiro/hooks/README.md:9–10`, nit**

## Review

1. `app/src/styles/tokens.css:192` **should-fix**. `--measure-wide: 80ch` (used at `StepHeader.module.css`, `.lede` in the ≤720px-high media query) goes beyond the 60–75 characters per line in design.md §4. Changing it to 75ch or less would fix this; the lede will need to be checked again at 1000×600 to see whether it still fits on two lines.

2. `app/src/components/shell/StepNav.module.css:72` **should-fix**. The switch from the full label to the short one relies only on `.item:has(.short)`. In a browser without `:has()` support, both spans show. The link would then read "What to check next Next questions", both on screen and as its accessible name (R12.3). The fix is to hide the full label without depending on `:has()`, for example with a marker class or data attribute on the item, or on the label itself.

3. `app/src/components/shell/StepNav.tsx:11` **nit**. At 901–1120px the nav says "Next questions", but the page title and the other widths say "What to check next". One concept now has two names. The accessible name always matches the visible text, so WCAG 2.5.3 is still met. Using one consistent short wording, or keeping the original name, would fix this.

4. `app/src/components/shell/StepNav.module.css:81` **nit**. The comment "Under the brand (laptop, tablet, phone)" is now out of date: at 901–1120px the steps share the brand's row. Update the comment.

5. `app/src/components/shell/TopBar.module.css:89-116` **nit (please confirm)**. The two-row layout now only kicks in at ≤900px. Tall screens 901–1120px wide, such as a 1024×768 tablet, also switch to one row with no demo chip. This is not limited to short viewports. If that is intended, the comment should say so.

Points checked with no problem found:
- **1440×900:** wider than 1120px and taller than 720px, so none of the new media queries apply. Unaffected.
- **375×812:** narrower than 901px. Only the ≤900 and ≤600 rules apply, and they behave as before (the old ≤1120 tablet rule still covers this width). Unaffected.
- **Tokens:** every new value comes from an existing token. `--topbar-height` follows the overridden `--topbar-h`. The 56px top bar still fits the 44px tap targets (R12.5).
- **Demo labelling (§7, R10.2):** the demo chip is hidden at 901–1120px, but `StepHeader` renders on every step (`App.tsx`), so its kicker and `DemoCaseLabel` still label the demo case.
- **Contract and safety:** the disclaimer and attributions are untouched (R9.1, R8.1). No API or type changes, so `docs/CONTRACT.md` does not apply.
- **Scope:** all five files are inside `app/src/styles/**` and `app/src/components/shell/**`.

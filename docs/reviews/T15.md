**Findings**

1. **`app/src/features/ranking/index.tsx:181` and `ranking.module.css:61-75` (should-fix):** the approved B1 layout is not followed. All candidates are full cards of the same size, each with all its evidence, a border and a shadow; rank 1 only has a heavier border and shadow. The approved design is: one rounded main panel (surface background, no border) for the closest match; the other candidates in a sidebar, quieter, showing only the name, a one-line overlap summary and a small dot bar. Right now the `.layout` sidebar holds `FeatureAside`. Fix: make rank 1 its own main panel; turn ranks 2–5 into compact sidebar entries that can expand to show evidence or go to "Compare side by side"; move "Features used" somewhere else (for example below the main panel, or as a collapsible section).

2. **`ranking.module.css:160-163`, `FrequencyMark.module.css:34` (should-fix):** the accent colour is used for every candidate's overlap label and frequency dots. The approved direction reserves the accent for rank 1, its dots, footnote numbers and the focus ring; secondary candidates use neutral colours such as `--mark`. Fix: use neutral colours for the overlap labels and frequency dots from rank 2 onward.

3. **`CandidateCard.tsx:55-63`, `:163-169`, `FeatureAside.tsx:30-36` (should-fix):** the footnote linking relies only on `onMouseEnter`. Neither evidence rows nor feature items can take focus, so keyboard and touch users cannot see the linking (breaks R12.1 and the approved direction's "hover, focus or tap"). Also, the original sentence is not shown next to the evidence row: on phones the original sentence is in the sidebar at the very bottom of the page, far from the evidence. Fix: make the rows focusable, or put a button in the row, so focus and tap both trigger it; following the approved direction, show the original sentence in an overlay above the row without causing layout shift.

4. **`format.ts:27-29`, used in `questions/index.tsx:285` (should-fix):** two different cases are shown as the same sentence:
   - `discriminates[].frequency === null`: the disease has no annotation for this feature at all;
   - `FrequencyInfo.label === null`: there is an annotation, but no frequency is given.

   Both show "Frequency not listed". On the questions page, "not listed" is exactly what tells the candidates apart. The current wording implies the feature is listed and only its frequency is unknown, and it does not match the footer note "Not listed means…" (contract §7.5 step 6, R3.7). Fix: show "Not listed for this condition" when `frequency` is null; show "Frequency not listed" only when there is an annotation without a frequency.

5. **`format.ts:14-24`, `FrequencyMark.tsx:44` (nit):** the frequency graphic uses 5 marks. The approved direction is a 4-dot graphic with a "Not recorded" dash. Fix: align with the art direction; if Obligate must keep its own step, ask Ian to confirm first.

6. **`index.tsx:181`, `questions/index.tsx:185` (nit):** `data-stale` is set, but neither CSS file has a rule for it, so the "stale" state makes no visible change to the list (and the opacity transition on `.list` has no effect). Fix: add a light fade style, or remove the attribute.

7. **`CandidateCard.tsx:190` (nit):** `c.score` is printed as is. If the service returns a long decimal, it will look over-precise (design.md §7). Fix: show a fixed 1–2 decimal places, still labelled "raw service score".

8. **`questions/index.tsx:39`, `:61-70` (nit):** the `answers` used for undo are component state and are lost when the step changes; on return, answered questions no longer show Undo. Fix: accept this and say so in the handover, or infer whether undo is possible from the term's provenance and updatedAt.

9. **Out of scope, a reminder only, not a T15 problem:** `app/src/styles/tokens.css` in this worktree and on `origin/main` is still Geist, not Newsreader plus Source Sans 3, so the B2 typography does not take effect in the app at all yet. That file belongs to the shared/tokens task and needs its own claim.

## Review

Problems found:

1. **`app/src/shared/mocks/responses.ts:329-336` (also 95-98, 116-118, 135-137, 154-156, 339-340), blocker.** The offline mocks give real diseases (Duchenne, Marfan, Kabuki 1, CdLS 1) and real HPO terms invented frequency bands, for example labelling each of the demo patient's own features "Very frequent" / "Frequent" in turn by position. The candidates also claim `sources: ['monarch-semsim', 'hpo-annotations']`, so the results footer shows the Monarch attribution even though this data does not come from Monarch at all. The page does carry a "Demo data (offline mock)" label, but this still violates CONTRACT §1 ("No component invents … frequencies"), R9.3, R3.4 and design.md §7 "Sources next to claims". The comment "no disease fact is invented" does not hold for the real-disease rows. Fix, any one of:
   - set mock frequencies for real diseases to `frequency: null` or `label: null`, and show "frequency not listed" in the UI;
   - replace them with the real values read from JAX on 2026-10-24, with the source noted;
   - for real diseases, keep only name, id and gene, with no frequencies.

   In addition, the `sources` of mock candidates should not include `monarch-semsim` or `hpo-annotations`.

2. **`app/src/shared/api.ts:290-303`, blocker.** Production also falls back to mocks automatically: whenever the browser thinks it is online and a network error occurs, or a 404/501 is returned, or a non-JSON 2xx is returned, mock data is used instead. After deployment, if a function is not written yet or there is a temporary network failure, judges will see the invented rankings from finding 1 instead of the error message plus "Try again" that R11.3 requires. This also bypasses the 502/504 + `retryable` semantics in CONTRACT §4. Fix: automatic fallback only under `import.meta.env.DEV` or `?mock=1`; in production, throw network errors as retryable errors. The real demo fallback comes from the server's `source: "demo"` (CONTRACT §7.4 table).

3. **`app/src/shared/store.tsx:186`, should-fix.** `setNotes` silently truncates text longer than 8,000 characters. This violates R1.2, which requires keeping the user's text and showing "Text is too long". `extract()` in the same file has a check (`api.ts:347`), but after truncation it can never be reached. Fix: the store keeps the text as entered, and intake shows the overflow and blocks submission.

4. **`docs/ART_DIRECTION.md:34` versus `app/src/styles/tokens.css:4`, should-fix (process issue, outside this task's scope).** The tokens comment says "Ian picked the white direction", but "Approved by Ian" in ART_DIRECTION.md is still PENDING. design.md §1 and the first item of §12 require approval before UI is written. Fix: record Ian's approval (date plus screenshot) in T12, or mark the tokens comment as not yet approved. This task does not change that file.

5. **`app/src/shared/store.tsx:209-212`, nit.** On re-extraction, all non-manual terms are replaced, so the user's "removed" or "excluded" changes to LLM terms are lost silently (R2.6). Fix: keep the user-set status for the same `hpoId`, or warn before re-extracting.

6. **`app/src/shared/mocks/responses.ts:57`, `:426`, nit.** `dataVersions.demoCache` is set to `'offline mock'`, but CONTRACT §5 says it is the recording date; the mock also reuses `source: 'demo'`, mixing it up with the server demo cache. `DemoCacheLabel` will show "Demo data (recorded offline mock)". For now the label priority already shows the mock label first, so the impact is small. Fix: put a date in `demoCache`, or explain in a comment that the mock does not follow this field's meaning.

7. **`app/src/shared/mocks/responses.ts:512`, nit.** `TestSuggestion.source` is set to the candidate's `diseaseId` (for example `ORPHA:558`), but CONTRACT §7.4 step 4 states that ORPHA annotations have no genes; genes come from OMIM (for example `OMIM:154700`). Fix: set `source` to the id of the annotation the gene actually came from.

8. **`app/src/shared/mocks/responses.ts:219-231`, nit.** The mock for non-demo text returns 200 with zero terms, while the real contract returns 422 `NO_TERMS_FOUND` or 503 `LLM_UNAVAILABLE` in this case. So T14, developing against mocks, cannot test the error paths of R2.9 and R10.4. Fix: have the mock throw the contract's errors.

9. **`app/src/shared/ui/AppFooter.tsx:16`, nit.** Before data is loaded, the HPO version shows "not loaded yet". R8.1 requires the version to be shown. Fix: acceptable as is, or use a fixed known version constant (CONTRACT open question 6).

10. **`app/src/shared/api.ts:459`, nit.** The abort listener that `health()` adds to the external signal is never removed. Fix: remove it in `finally`.

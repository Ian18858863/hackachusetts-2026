## Review

Findings for T18f (commits `d917c27` and `d289168`):

1. `functions/_lib/fallback/trials.ts:77,108`, should-fix. Contract §7.6 defines `total` as the upstream count. It is now an estimate (upstream count minus the studies dropped on one page), and after the broader search it takes the max across two different queries. Either send the real upstream `totalCount` of the query that was used, or record a `[CONTRACT CHANGE]` that redefines `total`.
2. `functions/_lib/fallback/trials.ts:118`, should-fix. `query.condition` now echoes the broader term instead of the request. The R7.2 empty-state link and the UI label can then name a different disease than the candidate the user clicked. Keep the requested condition in `query.condition`, or get §7.6 changed and confirm with the app owner that the new meaning is acceptable.
3. `functions/_lib/fallback/trialRelevance.ts:34-38`, should-fix. One shared word counts as relevant. `"niemann"`/`"pick"` would accept Pick disease (frontotemporal dementia) studies, and `"muscular"`/`"dystrophy"` would accept Becker or limb-girdle studies for Duchenne. That weakens R7.1 and design.md §7 ("sources next to claims"). Require all distinctive words of the name, or a phrase match.
4. `functions/_lib/fallback/trialRelevance.ts:36`, nit. A name with no distinctive words silently returns zero studies. Fall back to the unfiltered results, or add a warning.
5. No tests were added for `distinctiveWords`, `broaderCondition` or the 2-call cap. Task 2.8 is unclaimed, so this is not a scope breach, but the logic is untested.

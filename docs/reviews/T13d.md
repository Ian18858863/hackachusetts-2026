**Findings**

1. `app/src/shared/mocks/responses.ts:546` and `:565`, **should-fix**. When the user edits the `demo-npc1` terms, the response still uses the order and raw scores recorded for the original 12 terms. Only the evidence is recomputed. The UI would then show a "raw service score" and a rank that the service never produced for the current terms. This matters because `?mock=1` also works on the live build and could appear in a video. The caveat is only in a code comment (R3.5, R4.1, design.md §7 on false precision). To fix it, either use the recorded order and scores only when the term set equals the recorded set, or label the response so the app can say the order comes from the original demo terms.

2. `app/src/shared/mocks/recordedNpc1.ts:24`, **should-fix**. The header says "Generated from the saved responses; do not edit values by hand", but the raw Monarch, JAX and ClinicalTrials.gov JSON and any generator script are not in the repo. Nobody can check that the values are real (R9.3, design.md §7 on sources next to claims). To fix it, commit the raw responses or the script inside the claimed scope, or reword the line to say where the recordings are kept.

3. `app/src/shared/mocks/responses.ts:690`, **nit**. The trials response replaces `query.condition` with the recorded query ("Niemann-Pick disease type C"). The contract's `query` echoes the request. The swap is honest about what was searched, and the comment explains it. Note it in the contract or the app copy so the app does not present it as the user's own query (contract §7.6).

4. `app/src/shared/mocks/recordedNpc1.ts:72`, `:129`, `:166`, `:226`, **nit**. `categories` still lists `Inheritance` and `Clinical course`, although the header says those rows were removed. If the specialist table ever maps these categories, the brief could suggest a specialist from a category that is not an organ system. Drop them from `categories` or note in the header that they are kept on purpose.

5. `app/src/shared/mocks/responses.ts:381`, **nit**. `closestDemoCase` now goes through `DEMO_CASES`, and `demo-npc1` is first, so ties now go to npc1 instead of dmd. A manual term set that shares one term with npc1, such as Ataxia, gets the full Niemann-Pick differential. This only affects mocks, but check that it is intended.

**NOT RUN**
- I did not query Monarch, JAX or ClinicalTrials.gov live, so I could not confirm the recorded values against the upstreams. That includes whether `MONDO:0009757` has an Orphanet xref (if it does, contract §7.4 step 3 would make the `diseaseId` an ORPHA id instead of `OMIM:257220`), the GCLC gene on `ORPHA:33574`, and the 404 for `ORPHA:480556`.
- I did not check the UI rendering at the three design.md §12 sizes, the keyboard path or reduced motion.
- No tests were run, and the Vite build was not run.

Verdict: CHANGES_REQUESTED (findings 1 and 2).

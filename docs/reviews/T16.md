## Review

**T16 review (brief + trials, uncommitted changes, based on `26bb7d8`)**

The changes are all inside the claimed scope: `app/src/features/brief/**` and `app/src/features/trials/**`. `tsc -p tsconfig.app.json --noEmit` passes. All three hard acceptance checks are implemented at the code level: the one-page brief has a print stylesheet and `@page`; the phenopacket export downloads the `phenopacket` returned by `/api/brief` as a Blob; the trials list shows at most 5 entries and has an empty state.

1. **`brief/BriefStep.tsx:174`, `:190`; `brief/useBrief.ts:73`, should-fix.** After a brief request fails, `phase` becomes `error` and `updating` becomes false, so the toolbar is enabled again. The old brief is still on screen, and the user can print or export a brief and phenopacket that do not match the current terms. Also, `blocked` is cleared only by clicking retry; changing the terms does not request again. This breaks R6.2 (the brief should reflect the current case) and R11.3. Fix: when the old brief does not match the current case, disable "Download PDF" and "Export phenopacket" and mark it clearly as "out of date". Clear `blocked` when the case changes.

2. **`trials/recordedTrials.ts` (whole file) and `trials/TrialsPanel.tsx:62`, should-fix.** This file is a demo cache (31 KB) placed in the app. Under CONTRACT §3 and §9, the demo cache belongs to Jerry, in `engine/demo/**`. `functions/api/trials.ts` on origin/main already falls back to `getDemoTrials` when the upstream fails, so this path is now barely reachable, and it makes the app and the engine each keep a copy of demo data. The data in the file also does not follow the contract: it keeps `"NA"` phases (the contract requires `[]` when there is no phase, and the server filters out `"NA"`), and it has an HTML entity `Behcet&#39;s`. Fix: after rebasing onto origin/main, delete this file and the dynamic import, and rely only on `/api/trials`.

3. **Branch is behind, should-fix.** The worktree is based on `f77cc31`, while origin/main is `3c99583`. This review read the code against `functions/api/brief.ts` and `trials.ts` on origin/main, and did not actually run the merged version. Fix: after rebasing, run the whole demo-dmd flow with the real `/api/brief` and `/api/trials`.

4. **`brief/BriefStep.tsx:243`, should-fix.** The button says "Download PDF", but it actually opens the print dialog. CONTRACT §7.7 says "Print or save as PDF", and design.md §3 requires concrete copy that does what it says. Fix: use the contract's wording.

5. **`brief/BriefDocument.tsx:67`, nit.** When `demoLabel` is missing, the fallback copy `'Demo case'` is not the §13 text. The server currently always provides `demoLabel`, but the fallback copy should also use the prescribed format, or not be shown at all.

6. **`brief/BriefDocument.tsx:71`, nit.** `demoSource` requires `source === "demo"` and a non-demo case. But the server returns `source: "demo"` only when the case itself is a demo, so this branch can never fire under `/api/brief`. Delete it, or note that it applies only to mocks.

7. **`trials/TrialsPanel.tsx:225-226`, nit.** Singular or plural is decided by `data.total`, but the count shows `Math.max(total, studies.length)`. When `total` is 0 and `studies` has 1 entry, it shows "1 of 1 recruiting studies". Both places should use the same number.

8. **`recordedTrials.ts:46`, nit, for recording the video.** The Marfan results include unrelated studies, such as cholangiocarcinoma. This is what ClinicalTrials.gov returned, not a code bug. But shown as "recruiting studies for Marfan syndrome" in a demo, it will stand out.

**Checked, meets the requirements:**
- **Safety framing (design.md §7 and R9.1–9.4):** the printout also has the disclaimer, at body size. Results are a ranked list and do not read like a verdict. No raw scores and no percentages are shown (R3.5). Evidence is written as "Matches X of Y". When no frequency is annotated it says "frequency not listed" (R3.7).
- **Brief content:** specialists and tests are shown only when the server returned entries (R6.3); attributions and data versions use the server's values directly (R8.1, R8.2).
- **Trials:** shows title, phase, conditions, countries and link (R7.1). The empty state has a ClinicalTrials.gov search link (R7.2). The credit line is shown (R8.2). Loading shows a skeleton with real step names (R11.1), and results are announced through `aria-live` (R12.3).
- **R7.3 (RECRUITING only):** this relies on server-side filtering; the client does not filter again. Acceptable.

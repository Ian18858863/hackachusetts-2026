## Review

1. `functions/api/rank.ts:9` and `functions/_lib/fallback/rank.ts:396`, should-fix. The new header comment says a response is not cached when "an annotation or Orphadata call lost data". The fallback path, which is the production default, sets `complete` from annotation failures only (`annotations.every((a) => !a.failed)`). So when Orphadata fails, the fallback still caches a response for 24 h without the Orphanet preferred name or the `orphanet` data version. That breaks the T18h claim "never caches a response whose enrichment is incomplete" (contract §7.4 step 10, R11.4, R3.8). Fix: have the fallback also mark the result incomplete when an Orphadata lookup fails (as distinct from a lookup that answers with no data), or narrow the comment to annotation failures only.
2. `functions/_lib/fallback/questions.ts:56`, nit, in scope. This changes the `HPO_VERSION` import to come from `engine/index`, which re-exports it (`engine/index.ts:32`). The change is harmless but outside the stated purpose of T18h and T18i. Mention it in the commit message or the task record.
3. `functions/_lib/fallback/rank.ts:128` and `:232-250`, no defect found. The fallback now uses the same rule as `engine/rank.ts:195` and `:359-371`. An exact match always counts. A broader-term match counts only when the shared ancestor has an `HP:` id and is not in the excluded set (root, Phenotypic abnormality and its direct children; `HP:0000001` and `HP:0000118` are in both sets). Evidence fields still match contract §5 and P6 still holds (R3.4, §7.4 step 5). The `X-RDD-Enrichment` header is QA-only and does not change the response body. The fallback default for `RDD_ENGINE_PATH` is unchanged. Section 7 safety framing is not affected because there is no UI change.

CHANGES_REQUESTED. NOT RUN: TypeScript typecheck (`tsc` is not installed in this worktree), function tests, a live or forced-failure smoke test of `/api/rank`, and the engine path against a real Orphadata outage.
